# 学习恢复与固定站立策略的独立交接评测

正式评测边界由`contracts/wheel_leg_recovery_handoff_evaluation_v1.json`定义。恢复策略使用原checkpoint、原动作/观测接口和原恢复/故障门槛；固定站立策略使用SHA绑定的16001更新ONNX、50Hz策略、200Hz物理/PD、腿尺度0.5rad和60/2反馈，不启用气簧力矩前馈。物理气簧继续存在。

两种策略的35维观测含义不同，不能仅按维数连接。`controller_handoff.py`只按具名电机轴重排六轴向量；站立策略必须从编码器、IMU、命令及自身上一动作重新构造观测。恢复策略自身的位移观测、有效位和上一动作不能直接传给站立策略。

`RecoveryHandoffGate`接受原任务的实际完成事件及当前recovered/stable/terminated判定，另要求连续0.3秒的严格倾角、角速度和电机速度门槛。reward、更新计数和标称站立姿态不能代替完成事件。门槛只给出可尝试交接的时刻，完整站后窗口仍须独立验收。

`PhysicalTimeWheelResponse`是独立评测可选的物理时钟响应。轮命令的时间戳历史跨物理步长变更保留，容量与被动摩擦继续使用已识别模型。腿部一阶响应通过`set_motor_response_dt`重算系数而不清空状态或替换外层通信包装。原训练默认响应不变。

原生评测入口接入这些组件时，必须在第一次物理动作之前选定物理时钟响应，并保留同一个对象至站后结束。不能在交接时将原固定步缓存替换成一个新对象。改变物理步长时还须逐项验证仿真器、云台时钟、传感器、反馈与命令传输、域随机化滤波和接触积分；仅改变一个`dt`字段不足以完成环境集成。

`scripts/evaluate_recovery_handoff.py`提供单案例独立入口，使用原检查点的解析合同、姿态库和恢复控制，明确要求`--num-envs 1 --domain-randomization off --headless`。原训练环境源码和被动准入哈希校验保持原样；单进程构造阶段临时选择物理时钟轮模型，构造完成立即恢复默认工厂。每个恢复物理步在原`robot.update`之后记录原始接触力与全关节状态；失败保留原终止条件并直接结束案例，退休重置不再写回物理状态。原生运行回执独立于已有训练准入，不能用旧准入替代新适配器验证。

只有原实际完成事件和连续捕获同时成立才交接。切换保留同一物理对象、轮延迟、一阶响应和所有已有反馈/域/云台状态，并保存前后回执；新策略从编码器、IMU和自己的上一动作构造35D。当前仅支持经显式核查无随机延迟/噪声的标称域，任何活动通信或随机响应拒绝切换。站后按原恢复资产保留移动云台与物理气簧，使用固定16001的50Hz动作、200Hz物理/PD、60/2与0.5rad尺度且无气簧前馈；该资产云台与16001训练中的固定云台不同，需单独测量，不能将策略接口一致当作环境等价。

`--mode standing-reference`是独立站立对照，不提供恢复完成事件或实际交接。完整10秒站后窗口保留，不因后续翻倒选择更短的好片段。原始轨迹和每刚体20ms正world-Z冲量只作仿真诊断，约200Hz的站后物理不能分辨2ms接地验收。配置预检、CPU测试和单案例原生运行都不授予多姿态能力或硬件资格。

交接回执须包含物理位置/速度相等、执行器对象身份、轮命令延迟缓存和电机滤波状态相等、全部配置的反馈/通信历史，以及切换前后两个actor各自的动作历史。每个物理更新后用实际完成间隔积分接触力；逐刚体20ms积分完成后再按组取峰。

CPU函数测试、固定网格对原模型一致性和标称站立回放仅验证接口。原生入口逐步核验PhysX时间与步计数、保存两个actor各自的输入与输出；能力判定仍须包含实际学习恢复、同一物理轨迹的固定策略交接以及完整站后窗口，并保留全部失败分母。入口实现本身不提供行为通过结论。
