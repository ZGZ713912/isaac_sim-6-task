# WheelBipe V8 起跳能量与完整跳跃动作

`foundation-jump-v8` 是独立的新实验合同，定义在
`contracts/wheelbipe_foundation_jump_v8.json`。目标是在现有执行器边界内，
通过有效蹬地提高起跳能量，随后双侧收腿增加净空，下降时伸腿，接触后压缩吸能并接稳。
候选实现不等于已训练成功，也不把未测的最大高度声明为实车上限。

## 模型、接口与历史版本

V8 从 V7 派生，保留完整闭链、气簧、右腿独立摩擦辨识、圆弧行驶、
平台课程及非跳跃任务配额。策略/物理/反馈 PD 仍为 50/200/200 Hz，
腿 PD 80/1.5，四个腿电机各 ±40 N·m，轮端各 ±4.5 N·m。
保护仍使用实际 40°–110° 机械角度；虚拟目标越界与收腿方向的局部气簧补偿沿用 V7。
native effort limit 包含被动摩擦余量，不增加电机允许的电气力矩。

actor/critic/action 维度仍为 35/78/6。整车质心、真实接触和轮底净空只进入
奖励与诊断，不进入 actor，不推进请求时钟，也不改变控制器阶段。
质心使用每个刚体的实际质量、世界系 COM 位置及 COM 线速度加权，
不能以车体根节点的升降代替整车动量。接口来源为
[Isaac Lab ArticulationData](https://isaac-sim.github.io/IsaacLab/main/source/api/lab/isaaclab.assets.html)。

V1–V7 的合同文件、奖励及命令序列保留。V8 改变了奖励和成功判定，
必须新建 actor、critic、空 Adam，从零训练；不可把旧检查点作为同一课程恢复。
后续同 V8 合同的显式中断恢复仍遵守原总更新预算。

## 蹬地与起跳能量

旧版本在目标速度附近使用高斯奖励，超过参考速度会减少支付。
V8 使用两项单调、有界的支付，奖励的是形成向上动量的进展，不直接奖励大力矩或大接触力。

- `jump_push_velocity`：在请求已经进入蹬地、车轮确实支撑、机身近似直立、
  无非轮接触、尚未确认首次飞行的阶段，计算
  `score = 1 - exp(-(max(v_com_z, 0) / 2 m/s)^2)`。
  每次物理步只支付本次请求历史最好 score 的增量，乘 4。
  反复降低再升高到同一个速度没有新增支付；整个采样过程的增量总和不随物理频率改变。
  超过原定蹬地时窗的真实发力仍可获得支付，截止于首次确认飞行或请求超时。
- `jump_release_energy`：首次双轮离地样本保存 COM 速度，连续离地确认后支付一次
  `4 * (1 - exp(-max(v_release_com_z, 0)^2 / (2*g*0.25 m)))`。
  这是按单位重量归一化的竖直动能，不把 40 ms 后的确认速度误作离地速度。
  未确认就重新接触的候选离地会清除基线。主动离地还必须先有真实支撑蹬地，
  预蹲或重置产生的反弹不能单独赚取主动离地/能量事件。

`2 m/s` 与 `0.25 m` 是奖励尺度，不是测得的速度/高度上限。
较高的合法离地速度仍获较多支付。指令高度轨迹仍由请求参数和时间生成，
但蹬地高度跟踪奖励停止于预蹲准备段，不与更强起跳争夺轨迹。
原有错过起跳代价、摔倒与机械安全项仍保留。

请求期间 `joint_torque` 代价取普通值的 0.5；测得的支撑蹬地再乘 0.1，
即原值的 0.05。腿速度、加速度与动作变化代价继续保留请求期间的缩放。
普通运动任务的系数不改变。静止顶住限位，即使电机满输出，也没有速度进展或离地能量支付。

## 收腿、伸腿与缓冲

空中收腿目标保留 80 mm，最低双侧回收量保留 40 mm。
V8 的收腿进展单调增加至目标后保持饱和，不因超过 80 mm 而失去高斯核奖励。
稠密收腿权重为 4，下降伸腿权重为 1；双侧进展和逐腿进展各占一半。
实际两轮最小轮底净空另有 `jump_clearance` 支付。

主动跳跃成功（包含平台主动请求）需要按顺序满足：

1. 相对首次离地基线，两腿均回收至少 40 mm，并在尚未切换伸腿时连续保持 40 ms。
2. 顶点后进入下降伸腿阶段，两腿都相对空中最短长度伸长至少 25 mm，且发生在触地之前。
3. 首次接触后，两腿都相对首次触地长度再压缩至少 20 mm。
4. 首次离地之后整车 COM 至少上升 40 mm，且通过原有顶点/平台上表面、姿态、
   双轮稳定接触、速度跟踪及接稳持续时间条件。

伸腿奖励的阶段参考只在物理观察器内计算。顶点后的保持时间达到 40 ms，且用
实际轮底间隙和 COM 速度估算剩余下降时间不大于 120 ms 时，锁定伸腿阶段；
不大于 50 ms 时允许提前进入，以保留触地前伸腿窗口。长滞空不会仅因为顶点后过了
40 ms 就立即伸腿。这个弹道时间估计不是控制器输入或地形传感器。

被动空投保留独立诊断，不强制主动收腿序列。平台 drive-off 仍使用原有平台观察器，
不能把它的落地当成主动起跳成功。

## 冲击与计量单位

`jump_impact` 只使用已确认飞行之后的触地竖直接触力峰值。
同一策略间隔内先有高峰、后衰减到支撑力，也保留高峰。
充分蹬地的接触力不再被这个落地项处罚。原有平台撞壁与离台后冲击项保留。

物理步累计的速度增量、离地事件和净空支付先除以 `policy_dt`，
再由现有 RSL-RL 奖励入口乘一次 `policy_dt`。其他密度奖励继续每步只乘一次 dt。
新增 `JumpSequence/<task>/paid_*_mean_per_step` 是真正加权后的支付；
旧 `Mixed/reward/jump_air_tuck_mean_per_step` 等 tag 仍保留原始形状语义。

## TensorBoard 与逐回合分母

新增指标都写入原训练 event，不新建独立训练曲线源：

- `JumpSequence/<task>/*_episodes_total`：完成、成功、终止、确认飞行、落地、
  顶点、尝试蹬地、收腿保持、伸腿和缓冲的累计回合数。
- `success_fraction`：成功回合数/完成回合数，不累加每更新的每步事件均值。
  曾经接稳成功但在回合结束前又摔倒的回合，完成统计仍按失败处理。
- 离地 COM 速度、离地后 COM 上升、双侧最大收腿、两轮最小净空的最高值。
- 蹬地正功 J、净竖直冲量 N·s、蹬地时长、支撑力峰值、逐轴平均绝对力矩、
  逐回合峰值的均值，以及电气力矩达到名义 40 N·m 的 95% 的时间比例。
- 首次触地下行 COM 速度、落地竖直力峰值、双侧伸腿量、触地后压缩量与收腿时延。

均值按任务分开：push 指标以尝试过蹬地的完成回合为分母；release/flight 指标以确认飞行的
完成回合为分母；landing/buffer 指标以已落地的完成回合为分母；收腿时延以完成保持的回合为分母。
缺少样本时数值为 0，需同时查看对应计数，不能解读为通过或完美表现。
累计统计只覆盖当前进程，不跨恢复尝试伪装成全谱系统计。
训练时这些累计计数和比率由 PPO 更新边界直接写入 logger，避免进入 `ep_infos`
后再被按 rollout 步数平均成小数“总数”。只读逐步评测则直接记录该物理时刻的快照。

车体净空另记录根部碰撞 AABB 在顶点的保守下界，明确标为 `lower_bound_m`，
它相对地面平面，不是精确车体碰撞距离，也不作为平台成功依据。

## 离线执行器扫描

`scripts/probe_wheelbipe_jump.py` 使用外部时钟的腿长目标经过原六轴动作、反馈 PD、
力矩限幅、辨识摩擦、延迟和真实气簧路径运行。默认不创建 actor，始终不创建 optimizer。
两轮倒立摆若无法在零轮速目标下保持准备段平衡，可以显式传入 `--checkpoint`，
只读加载一个 35D actor 作为准备段和轮控制的稳定基线；请求开始后四个腿目标仍由扫描接管。
回执记录 actor 是否存在及检查点 SHA，检查点前后校验一致。
无论是否使用稳定基线，都不改训练中的策略、不做 teacher/donor、不写实车接口。

```bash
# 先查看候选；不会启动仿真。
python scripts/probe_wheelbipe_jump.py \
  --output .codex/report/jump_v8_probe_new --plan-only

# 使用已配置的 Isaac Sim 5.1 / Isaac Lab Python，输出必须为新目录。
/path/to/isaac-env/bin/python scripts/probe_wheelbipe_jump.py \
  --num-envs 64 --steps 320 \
  --crouch-lengths .16 .20 .24 --push-holds .08 .12 .18 \
  --output .codex/report/jump_v8_probe_new
```

需要稳定基线时，在扫描命令上显式追加 `--checkpoint /absolute/path/model.pt`。
此参数仅属于离线评测；新 V8 训练仍为全新 actor、critic、空 Adam。

扫描默认固定 nominal 物理；requested 域随机化需显式选择 profile 与 strength。
每个非跳跃任务保留至少一个环境，其余环境分配到各候选。目标干预按相同请求时钟完成
预蹲、满伸目标、收腿、再伸腿及恢复，接触与 COM 不参与目标切换。
结果保存逐回合数据、event、有效课程及源码 SHA。`best_observed` 只表示本次扫描中
已确认飞行且未摔倒的最高离地速度样本，不能作为全局最优证明。

训练/评测以 `--training-profile foundation-jump-v8` 显式选择。
新训练仍须先提交并冻结源码，再用现有 `trainctl wheelbipe` 生命周期启动；
本合同不负责自动停止已有 V5 进程或自动启动 V8。
固定平台评测入口 `scripts/evaluate_wheelbipe_scenarios.py` 也接受显式 V8 profile。
