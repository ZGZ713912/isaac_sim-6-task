# WheelBipe 运动与主动跳跃混合训练

`foundation-jump-v2` 是全新策略的工程训练配置，合同为
`contracts/wheelbipe_foundation_jump_v2.json`。它保留 v2.0.2 完整机械与碰撞、
50 Hz 策略、200 Hz 物理/反馈 PD、PD 60/2、腿转子惯量 0.015795 和
requested 域随机化。`foundation-jump-v1` 保留历史复现用途。

`foundation-jump-v4` 是收腿控制与奖励的新候选配置，合同为
`contracts/wheelbipe_foundation_jump_v4.json`。它使用 PD 80/1.5、有限的虚拟
目标越界和请求时钟控制的局部气簧补偿。v1–v3 保留历史语义；v4 改变了控制
与奖励，不能作为同一次历史训练的 `--resume`。配置存在不代表已获训练启动
或硬件运行授权。

## v4 收腿控制

`--leg-target-overtravel-rad` 控制成对电机的相对目标边界放宽量，v4 默认
0.2 rad，上限 0.35 rad。保持同侧电机目标均值时，默认放宽量由两个目标各
承担 0.1 rad，约 5.73°。v4 默认 `--leg-target-overtravel-scope jump-request`，
只在主动跳跃请求开始至结果截止期间放宽；普通运动、被动空投及请求前站立
保持原目标域。`all` 仅供显式对照。真实 40°–110° 机构角域、实际角度的向外力矩保护、
原生机械限位和每轴 ±40 N·m 电机上限全部保留。目标投影代价按放宽后的
虚拟目标域计算，机械跟踪滞后不会被算作不可达目标。

气簧物理力始终保留。v4 的 `--tuck-spring-compensation model` 在现有编码器
气簧保持力矩模型上加入收腿方向的差动力矩，默认 `--tuck-spring-gain 0.75`、
`--tuck-spring-cap-nm 16`。只有主动跳跃请求的预定飞行时段内，目标相对角度
要求收腿且 PD 合力矩仍要求向内时才启用；误差从 0.02–0.10 rad 平滑爬升，
向内 PD 力矩从 0–2 N·m 平滑爬升。每条腿独立计算，保持共同转动分量为零。
PD 需要制动或伸腿时补偿归零。请求的蹲伏、蹬地、普通运动及被动空投环境
均不启用这个补偿。

控制切换只依赖外部请求时间、编码器和 PD 目标；实际接触、真实腾空、顶点
及奖励状态机不参与切换。时钟窗口本身不证明已离地。保持力矩模型在当前
反馈位置求值，超出有效几何分支时输出零。新增力矩与未裁剪 PD 相加后，
共同经过电机上限、强度随机化和真实角度保护；所有新增电机努力均计入电机
功耗及平滑代价。气簧模型仍带有辨识范围外外推假设，配置值未获实车认证。

训练和独立评测都接受 `--leg-kp`、`--leg-kd`、
`--leg-target-overtravel-rad`、`--tuck-spring-compensation off|model`、
`--tuck-spring-gain`、`--tuck-spring-cap-nm`。v4 默认值为候选对照值，
不是已确认的最优值。RMCS 控制与导出元数据必须另行对齐后才能部署，
本配置没有修改实车控制器。

## v4 收腿与落地奖励

首次测得两轮均满足离地条件时记录收腿基线，并保存随后 40 ms 连续离地确认
期间的双腿收缩；未确认就重新接触的候选会清空。主动起跳成功仍要求双腿
各收缩至少 4 cm，稠密目标仍为 8 cm。过程奖励一半采用双腿共同进展，另一
半采用两条腿各自进展的均值，避免早期只有一条腿进步时完全没有信号。

首次测得顶点后保持收腿参考 40 ms，再锁定切换到下降伸腿参考；离地计时
清零或竖直速度反弹都不会重新进入收腿阶段。原有 0.3 s 二次曲线落地缓冲、
普通运动奖励、跳跃20%和被动落地10%的配额保持。新增补偿请求力矩和门控、
顶点与伸腿阶段计数写入现有 TensorBoard event。奖励上涨仍需独立行为评测
确认，目标干预测试只用于区分执行器能力与策略学习。

## 任务与课程

v4可用 `--course-updates 10000 --iterations 10000` 将完整课程的更新节点
压缩为一半：运动阶段0/1000/3000/6000，跳跃难度5000时完全展开，运动中
跳跃在3000–6000逐渐加入，自旋在6000/7000展开。物理回合时长、0.3 s
落地缓冲、奖励尺度和任务配额不随预算缩短。显式课程预算须与训练更新
上限相同，实际合同与SHA保存在 `params/course.json`；恢复时保留该身份。
原20000课程不传此参数时保持原节点。独立评测也必须传入相同课程参数。

1024 个环境固定分配如下，重置不能覆盖其他任务的配额：

| 任务 | 比例 | 环境数 |
| --- | ---: | ---: |
| 站立 | 15% | 154 |
| 前进 | 15% | 154 |
| 后退 | 15% | 154 |
| 变高 | 10% | 102 |
| 转向 | 5% | 51 |
| 冲刺与刹停 | 5% | 51 |
| 双向自旋 | 5% | 51 |
| 主动跳跃 | 20% | 205 |
| 腾空后落地 | 10% | 102 |

每环境每次 PPO 更新采样 24 步。初期主动跳跃以静止起跳为目标；6000–12000
更新逐渐给约一半跳跃环境加入双向运动指令，最终幅度为 0.5 m/s。普通运动
沿用基础课程，不因跳跃环境失败而减少配额。目标顶点高度从 0.42–0.45 m
逐渐增加到 0.46–0.54 m，10000 更新达到全部难度。

## 指令与奖励

主动请求的时间、目标顶点和 7 维控制模式槽由外部参数及时间决定。现有高度
指令槽在请求期间显式给出蹲伏、蹬伸、飞行和回到站高的参考。物理接触、
是否飞过及落地状态仅参与奖励和评测，不推进参考轨迹，也不写入 actor。

准备阶段的高度奖励以保持原站高为零基线；蹬伸奖励同时比较目标向上速度
和实际向上进展。错过蹬伸且没有有效飞行的环境按秒支付失败代价；继续站立
不能取得跳跃恢复高度奖励。恢复高度奖励必须先发生真实飞行和落地。
离地、首次落地和接稳事件各支付一次，事件与密集奖励的时间单位保持分离。
运动跳跃的接稳速度条件比较实际机体系速度与当前指令，避免一边要求前进、
一边要求停止的冲突；静止跳跃仍须回到低速。

跳跃期间取消普通站高和竖直速度惩罚；腿速、腿加速度、腿动作平滑和动作
变化率代价分别缩放至基础的 0.2、0.2、0.1、0.2。普通任务的原始奖励权重
保持不变。PPO 继续使用原全局优势归一化；任务样本量、优势 RMS、回报 RMS
和分任务物理事件写入现有 TensorBoard event。

## 生命周期与验证

从零训练要求新 actor、新 critic、空 Adam 和零课程偏移，禁止加载旧策略、
teacher 或 donor。先提交并冻结源码，再使用 `trainctl wheelbipe` 管理的新
session 启动。`pause` 等待安全更新边界，`resume` 在驻留暂停时继续原进程；
`release` 属于另一个保存退出操作。参见 [trainctl](TRAINCTL.md)。

只读混合评测入口为 `scripts/validate_wheelbipe_mixed.py`，显式传入
`--training-profile foundation-jump-v2`、检查点、课程更新及输出目录。普通
站立、前后行走和双向自旋使用 `scripts/audit_wheelbipe_behavior.py` 的相同
profile。比较成功率时分开主动起跳与空中释放，按完成回合计数。

闭链距离保留原始峰值及逐任务超过 3 mm 的环境比例。孤立峰值不作为本配置
的训练门槛；多数环境受影响时才扩大调查。该工程监控口径不修改历史续训
验收合同，也不代替完整十三项能力和硬件认证。
