# 恢复抬升奖励接口

`contracts/wheel_leg_self_righting_geometric_lift_v1.json` 是相对
`wheel_leg_self_righting_encoder_increment_range_v1.json` 的单项奖励门控对照。
唯一配置变化是 `multi_pose_recovery.dense_reward` 的具名合同；新合同保留全部数值权重，
只将 `recovery_lift`、`recovery_lift_error` 两项的门控从双轮实际受载捕获改为姿态与支撑几何。

定义 `u = clamp(-gravity_z, 0, 1)`、
`a = 1 / (1 + (support_error_m / 0.12 m)^2)`，
`l = min(clamp(wheel_load_fraction / 0.15, 0, 1))`。
原合同的这两项都乘 `u² a l`；新合同乘 `u² a`。
高度核分别为 `exp(-((height - 0.305 m) / 0.06 m)^2)` 和
`log(1 + ((0.173 m - 0.305 m) / 0.08 m)^2) - log(1 + ((height - 0.305 m) / 0.08 m)^2)`。
两项权重仍为 4、2，单位为 reward/s，环境仍只乘一次 policy_dt。

支撑捕获奖励、捕获后的水平速度/角速率成本和车体接触成本仍乘原 `u² a l`。
原势差项已有接触前高度/支撑信号且保持原定义；新合同比较持续高度密度的不同门控，
不能解释为首次增加接触前信号，也不能将该假设认定为过去训练失败的唯一原因。
仰躺和精确侧倒的 `u=0`，没有这两项的抬升奖励。

全部输入仅在仿真奖励中使用。新合同不增加 actor/critic 输入、控制状态、目标、时钟或物理状态写入。
它不要求策略复制脚本轨迹；共同/相对增量、编码器采样、出生/使能上一动作、探索范围、
近起点课程、七类/四腿采样、原势差、时间/失败/冲量成本均沿用范围对照合同。
原恢复、稳定、机械/冲量终止和完整评测分母不变。
几何门控允许尚未双轮支撑的高度得到奖励，因此仍可能鼓励没有稳定支撑的暂态抬升；
行为必须由原实际恢复和完整窗口验收，不以奖励上升或低冲量失败代替。

设计参考：[人形起身的发现与收敛阶段](https://arxiv.org/abs/2502.12152v2)及
[轮腿恢复的动态奖励与协同](https://arxiv.org/abs/2506.05516v2)。
这里的具体门控是本项目的待检验对照，不是论文直接给出的轮腿参数。
新训练先提交冻结源码及合同、完成原生准入，再从全新 actor/critic/空 Adam 采用有限预算。
独立行为改善后才能另选全新长预算；已有策略不得作为 teacher 或 donor。
