# 整车失能倒地姿态采集

独立工作树：`/home/noir/.codex/worktrees/fallen-recovery/isaac_wheeled_rl_train`，分支 `dev/fallen-recovery`。本次只采集和整理被动倒地终态，不改训练入口、奖励、出生分布或训练中的源码，不启动 PPO。

整车使用已认证的 `model/wheel_leg_v2.0.2/training`：21 个刚体、20 个树关节、6 个外部闭链约束，总质量 21.44174 kg，云台 yaw 连续转动、pitch 保留机械限位。六个底盘电机与两个云台电机的驱动力矩、PD 全部为零；保留重力、接触、被动气弹簧、现有轮侧惯量及被动损耗。没有新增腿电机摩擦模型，待用户补充后重新采集比较。

按用户要求，本采集器临时把全部非轮碰撞体的静/动摩擦设为 **0.7**，包括外壳、底盘合并碰撞包络、云台与腿。非轮材质采用 `max` 合成，因此与摩擦 0.5 的地面接触时使用 0.7。驱动轮仍采用原来的 0.7、`average` 合成，与原地面的有效系数为 0.6。原资产与训练摩擦配置不写回修改；原生材质读回记录在结果中。

每次从七种闭链可行腿形之一开始：标准趴地、平衡腿、屈腿、伸腿、左短右长、左长右短、分腿。先解完整闭链，再随机设置云台 yaw ∈ [−π,π]，计算全部碰撞包络最低点，将整车轻放到离地 2 mm 处，根和所有关节初速度为零。之后不写任何位置或速度，只推进被动物理。所有初始配置都通过闭链与气弹簧行程检查。

默认规则扫描为 45° 倾角、45° 方位，共 26 个重力方向 × 7 种腿形 = 182 次；另加 256 次均匀 SO(3) 随机整车角度，总计 438 次。随机种子默认为 261031，每次独立随机云台 yaw。规则网格去除均匀平地上的整体航向重复；随机样本仍含整体航向变化。

```bash
cd /home/noir/.codex/worktrees/fallen-recovery/isaac_wheeled_rl_train
/home/noir/miniconda3/envs/isaacsim6/bin/python scripts/collect_fallen_pose_bank.py \
  --output reports/passive_fallen_20261031/sweep-new \
  --device cpu --num-envs 64 --random-placements 256 \
  --physics-dt-s .005 --settle-timeout-s 60 --wheel-convex-segments 64
```

本次正式扫描采用 5 ms 物理步长、64/32 求解迭代、每次最多 60 秒。采集器默认物理步长为 1 ms；支持 1/2/5 ms，以便做端点复放核查。每个批次默认最多推进 20 秒，`--settle-timeout-s` 可延长至 120 秒。`--prepare-only` 仅生成几何起点与来源，不能产生实际倒地结果。`--self-collision` 可以对照原生非相邻刚体自接触，默认继承资产关闭自碰撞的设置；开启后的保守碰撞包络是否造成内部伪碰撞必须先核查，不能把开关本身当成 CAD 接触认证。

连续瞬时低速的“严格落稳”判据为全部 21 个刚体线速度 ≤ 0.02 m/s、角速度 ≤ 0.1 rad/s，全部转动关节速度 ≤ 0.15 rad/s、滑动关节 ≤ 0.005 m/s，地面总竖直支持力为整车重力的 0.8–1.2 倍，连续保持至少 1 秒。云台速度参与该判定。

另设 2 秒端点窗口用于区分接触求解抖动与持续运动：根位置变化范围的三维长度 ≤ 5 mm、体坐标重力方向相对窗口末帧变化 ≤ 1°，每个转动关节变化范围 ≤ 0.05 rad、滑动关节 ≤ 1 mm，刚体及关节速度 RMS 仍使用上述低速门槛，平均支持力为 0.8–1.2 mg。它单独记为 `window_rest`，不覆盖原始严格落稳结果。结果汇总中“整车落稳”包含严格门或该窗口门通过的样本，文末分别列数。

另记录“车身和腿落稳、自由云台仍可能运动”的独立诊断，不将其升级为整车静止。闭链曾超过 3 mm、最终关节越界或实际碰撞包络穿地超过 3 mm 的样本单独拒绝。

结果中保留所有放置，包括未落稳及机械拒绝：

- `bank.json`：起点、每次原生终态、全部关节位置/残余速度、实际逐刚体位姿、逐刚体速度、支持刚体与接触力、落稳时间、闭链峰值、失败原因、材质读回及源文件哈希。
- `source/`：该次运行使用的采集源文件快照。
- `traces.npz`：10 ms 采样的根姿态、关节、最大刚体速度、接触力、闭链及落稳连续时间。它是采集轨迹，不是训练指标或替代 TensorBoard 的训练曲线源。

几何穿地检查使用原生逐刚体位姿变换碰撞包络，同时记录关节 FK 与实际位置差，避免在软约束有误差时仅用 FK 误判。原始采集 `poses` 只包含通过严格瞬时门的终态；后处理目录另保留窗口判定及其证据。保留整体 yaw、XY 和轮相位等价关系，保留腿形、相对云台 yaw 及接触支撑差异。每组代表均为真实测量端点，不通过平均四元数或关节角合成姿态。

有限放置扫描不能数学穷举实车所有姿态。不同腿角、自由云台 yaw 和接触位置可能形成连续的终态变化，最终应区分少量车身倒地方向与其中的连续构型。当前资产为保守凸包近似，并非所有 CAD 细节；原生落稳与自接触审计也不证明实车成立或 RL 已能自起。训练、实车自起及完成后的站立接地均留待后续独立验证。


## 碰撞表示与自接触核查

初始 CPU/GPU 对照发现继承的 USD Cylinder 轮碰撞表示在部分倒地终态出现约 22–25 mm 的名义圆柱穿地，FK 与原生位置却只差微米，因此拒绝这些样本，没有放宽穿地门。采集器默认将两个轮碰撞体临时替换为半径 60 mm、厚度 25 mm 的 64 边内接凸包，最大半径差约 0.0723 mm；质量、惯量、轮摩擦及损耗不变。替换只在独立采集场景中生效，训练 USD 未改。`--wheel-convex-segments 0` 仅保留用于复现该负例。

源资产除关闭自碰撞外，还过滤了全部内部刚体对。第一次只开自碰撞开关的对照无效；去掉非相邻过滤后，保守凸包在机构内部产生不合适的自碰撞并数值失败，负例完整保留。正式扫描继承原有关闭状态，再使用 **原始未简化 CAD 三角网格** 对每个终态做表面相交筛查：排除树关节、闭链相邻对及名义装配本来存在的相交对，新出现的非相邻相交或 CAD 穿地超过 3 mm 标为待复核，并从筛选后的目录中剔除。这只检查终态表面，不证明体积包含、全过程无自穿越或自接触动力学正确。

`fast-simplification==0.2.0` 与 `python-fcl==0.7.0.11` 仅用于离线绘图和 CAD 筛查，放在临时分析目录，未安装到训练环境。逐刚体 CAD 筛查不简化网格；绘图每个大零件目标 5000 面。

车身细分模式使用完整链接聚类：同簇所有终态的体坐标重力方向两两相差 ≤ 12°、车身高度范围 ≤ 35 mm，区分纯轮支撑。七个易读方向标签只用于总览，不预设细分簇数，也不把连续云台/腿构型强行合为一个完整关节姿态。目录保留每个真实端点及簇成员。

## 本次结果

完整原生扫描 **438/438**：182 次规则方向与腿形组合、256 次随机整车姿态；每次云台 yaw 随机。八个电机主动驱动力矩读回峰值 **0 N·m**。原始严格瞬时落稳 17 次，其中 16 次通过 CAD 筛查。另一个样本曾触发闭链 3 mm 护栏，峰值 9.388 mm，已拒绝；其余机械可用样本闭链峰值最大 1.923 mm。所有终态名义碰撞包络最低值约 −0.300 mm，没有轮穿地拒绝。

## 1 ms 代表姿态复放的限制

`representative_replay001` 在物理步进前因复放高度从 NumPy 推导为 float64 而被原生 Warp transformf 拒绝；已明确根/关节状态的 float32 类型，失败原件保留。`representative_replay002/003` 实际以 1 ms、64/32、相同临时摩擦和显式轮凸包，将代表端点重新轻放并零初速度运行 20 秒；源姿态的云台角度保留，不再次抽签。这是单独的重复放置检查，不是与 5 ms 逐帧轨迹等价对照。

覆盖七类的 8 次复放全部保持原车身方向标签，重力方向偏差均小于 0.9°，但 **0 次通过严格连续瞬时整车落稳门**。斜向代表 225 通过整车 2 秒窗口且 CAD 筛查无新增相交；正向趴地代表 411 仅车身与腿窗口通过；左右侧倒 107/81 只有车身方向稳定。车尾向下 153 与翻顶 96 的最后 2 秒根位置范围分别约 9.24 mm、30.48 mm，仍在缓慢滑移。车头向下的两个代表 360/125 出现新的 CAD 非相邻相交，需要复核，不能作为稳定姿态验收通过。

因此当前交付是 **倒地姿态候选目录和实际终态数据**，并没有确认七类都是长期稳定平衡。扫描的 158 个低速收敛端点只说明该次 5 ms 有限窗口满足门槛，不能覆盖 1 ms 负例。最终图同时标明两种步长的观测；`screened_endpoints.json` 附有复放状态，未复放的样本明确记 `not_replayed`。没有新增腿摩擦、云台锁定或人为停止运动。后续用户补充摩擦后，应在这个独立入口重新采集、复放和比较，不能直接沿用本轮的低速计数声称真实稳定或自起成功。

旧 `friction07_sweep001/bank.json` 的 `running` 是中断前保存的历史状态，其进程退出已在 `friction07_sweep001/closure.json` 单独核对；原件不改写。`preview_contact001/bank.json` 同样是带 partial 说明的运行中快照。两者均没有后台采集进程。
